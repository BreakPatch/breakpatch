The AI

AI that reads the screen, not your code.

The AI looks at your app's screen the way a person does, and it runs on your Mac. It never needs to see your code, and nobody has to write test scripts.

For developers: Qwen3-VL 4B, an open-weights vision-language model, run on Apple Silicon through MLX. No selectors.

Self-healing tests Team, coming later

Tests that fix themselves when a button moves.

A redesign shouldn't mean re-recording every test. When a button has moved, the AI finds it again from the step's description, re-checks it against how it looked when you recorded it, and the run carries on. The step is marked Fixed automatically.

  • The report shows the old position next to the new one
  • Accept new position, or dismiss it. Nothing changes until someone decides
  • Suites show Passed with fixes, or fail on any fix for release checks

Why on-device AI

The AI runs where your app already is.

AI testing usually happens in someone else's cloud. Breakpatch runs the test browser and the model side by side on your Mac, which changes what testing costs and what it can reach.

  • Unlimited runs, no cloud billThe model runs on a Mac you already own. Run a suite every hour or on every build: there are no per-run, per-screenshot or per-token fees, in any edition.
  • Private and staging appsIf your Mac can open it, Breakpatch can test it: staging behind a VPN, an internal tool, or localhost. No tunnel, and no vendor to let through your firewall.
  • No test data sent to an AI vendorScreens, steps and saved secrets stay on your Mac. There's no model provider in the loop, so there's no one else's AI to add to your data review.
  • An open model, the same every runThe model is published openly and downloaded once. The same model runs every time until you change it, so no one swaps it under your tests.

Three steps. No code.

If you can use your app, you can test it.

  1. 1

    Record

    Open your app in Breakpatch and use it the way a person would: click, hover, drag, type, upload. Each action becomes a step, and the AI names what you clicked.

  2. 2

    Replay

    Press Run, or run a whole suite. Breakpatch does each step again and checks the screen before and after every one. In Team, coming later, the AI also finds buttons that moved.

  3. 3

    See what broke

    The first thing that's wrong stops the run. The report shows what was expected next to what was on screen, why, and what to try.

Screen checks and the report

Know what broke, and why.

After every step, Breakpatch checks the screen changed the way it did when you recorded it. There's nothing to draw or approve. When a run fails, the report puts what was expected next to what was on screen, and says why in plain words.

Visual checking, not AI. Screen checks compare how the screen looks with how it looked when you recorded, leaving out the parts of a page that change by themselves, like clocks and carousels. The same screen gets the same answer every time.

  • Reasons like “Couldn't find the Done button”, not error codes
  • Re-record this step, straight from the report
  • Copy → Markdown, for an issue: a ready-made bug report for GitHub, Jira, Linear or any tracker
  • Why did this fail? Team, coming later The AI says in plain words what changed, like “The Save button now reads Save changes”, and what to do
  • Create issue Team, coming later in GitHub, Linear or Jira in one click, with the steps, the screenshot and a link to the report
Reading the report

Plain files

Your tests live in your repo.

In Community, every test is a readable JSON file in a folder you choose. Keep it next to your code and Git is your history: a change in the app shows up as a small, readable diff.

  • Shared steps: record Log in once and use it in every test
  • Saved secrets stay in your Keychain. Tests only store their names
  • Pull a change, switch back to Breakpatch, and it reads the folder again

Local runner and CI Team, coming later

Runs on a schedule, or from your pipeline.

Pick one Mac to be the local runner. It runs suites on a schedule and whenever anyone presses Run on runner, with one queue for the whole team. Start suites from CI, a script or an automation tool, and get the result wherever you want it.

  • Schedules like Mon to Fri, 06:00
  • Run requests from Codemagic, GitHub Actions, Bitrise or Jenkins
  • Result messages to Slack and Microsoft Teams, with the failed step, why, and a link to the report, or to any web address
  • A failing test can stop a release before it ships, with breakpatch-ci

Questions

Is it free?

Community is free and open source under Apache 2.0, with no time limit and no account. Solo, for one person, is $19 a month, or $16 a month billed yearly. Team and Business, the paid plans for working together, are coming later, and their prices aren't decided yet. See pricing.

Which AI model does it use?

A vision AI model that runs on your Mac and reads the screen. It's about 3 GB, downloaded once during setup, and unloaded when it's idle.

For developers: Qwen3-VL 4B, an open-weights vision-language model, run on Apple Silicon through MLX.

The AI names the steps you record. In Team, coming later, it also finds buttons that moved and says why a step failed. Screen checks don't use it: they're a visual comparison. See The AI assistant.

It's the only model for now. Bringing your own, a local one through Ollama or LM Studio or a cloud model, isn't available yet.

Does the AI need the internet, or cost extra to run?

Only to download the model once, during setup. After that it runs offline, on your Mac. There are no API keys and no per-run fees, in any edition.

Does my data leave my Mac?

Your tests, screenshots and saved secrets don't. The test browser and the AI model both run on your Mac. In Community your tests are files in a folder you choose, and nothing of them reaches our servers. Team, coming later, keeps them in a shared workspace: in your company's own Google Firebase project (see Create a workspace), or hosted by Breakpatch.

Community sends anonymous daily totals of tests created and runs, with no names, addresses or IDs. You can turn that off in Settings → Privacy. The manual lists exactly what's sent.

Which Macs does it run on?

A Mac with Apple Silicon (M1 or later), 16 GB of memory and macOS 14 or later. Intel Macs aren't supported. The AI model takes about 3 GB of disk space.

How do I install and update it?

Paste one line into Terminal and Breakpatch is in your Applications folder a minute later (once the public release is out: join the list to hear when). No password, no admin rights. After that it updates itself, so you're always on the latest version.

Want to see exactly what it does first? Read the script or the install guide.

What does Breakpatch send back to you?

Only what's needed to check a Team licence, never your tests. Community has no licence at all.

Team, when it comes, confirms its licence once a day and keeps working for 30 days without a connection. It sends the licence, who is using it (the person's work email, or the machine's name for a runner) and simple counts, such as how many tests ran and passed. Never test names, web addresses, steps or screenshots. The manual lists every detail.

Can I use it in CI?

Not with Community. Team, coming later, adds two ways. Your pipeline can add a run request, and the local runner runs the suite and sends the result to Slack, Microsoft Teams or any web address. Or run breakpatch-ci run --test on the CI machine: it tells your pipeline whether the test passed, so a failing test stops the build. Both will work with Codemagic, GitHub Actions, Bitrise and Jenkins. See Run requests and From CI with breakpatch-ci.
